# Результаты проверок

[English](validation.md) · [Русский](validation.ru.md) · [README](../README.ru.md#тестирование-и-подтверждённые-результаты)

Этот отчёт различает подтверждения из разработки и результаты интеграции со слов оператора. Он описывает прогон, предоставленный для пользовательского руководства, и не заявляет новый реальный прогон при работе над документацией.

## Окружение и источники

| Компонент | Зафиксированное окружение |
| --- | --- |
| Основной компьютер / контроллер | Ubuntu 26.04 со слов оператора; независимая проверка ОС для этой документационной задачи не проводилась |
| E2E-гость | Ubuntu Server 24.04 LTS |
| GitHub Actions | Ubuntu 24.04, как задано в [ci.yml](../.github/workflows/ci.yml) |
| Внешний production VPS | Не входит в подтверждённый E2E-прогон |

[PR #11](https://github.com/DanilFaritovich/portfolio-server-infrastructure/pull/11) описывает успешные offline-проверки линтеров, синтаксиса Ansible и Python, подтверждённую оператором подготовку VM (`ready`, базовый снимок присутствует), инициализацию всех этапов и независимую проверку SSH/sudo/Docker/UFW/systemd/финальной политики.

В разделе проверок PR также зафиксирована более ранняя остановка повторного прогона на скрытом запросе подтверждения; реальная проверка исправления, полной идемпотентности и перезагрузки оставлены ожидающими выполнения. Поэтому описание PR подтверждает подготовку/инициализацию, но не каждый результат последующего сценария.

Последующее подтверждение оператора, предоставленное вместе с этой документационной задачей, сообщает об успешных проверках:

- Финальная верификация, повторное выполнение и идемпотентность.
- Перезагрузка гостя и проверка после неё.
- Создание пользователя, проверка SSH, добавление и отзыв ключей, удаление пользователя.
- Безопасное удаление E2E-стенда.

[Таблица результатов README](../README.ru.md#тестирование-и-подтверждённые-результаты) объединяет эти источники с указанием их происхождения. Количество тестов, полный журнал, реальные inventory и данные доступа здесь не публикуются.

## Интерпретация и ограничения

Offline-проверки не доказывают удалённый доступ и работу сервера. Результат VM не подтверждает работу на внешнем production VPS, каждой допустимой версии Ubuntu, других дистрибутивах/архитектурах контроллера или WSL2.

Повторное применение должно сходиться без изменений управляемой конфигурации. Проверка Docker по-прежнему создаёт, запускает и удаляет временный контейнер и может заполнить кеш образов; эти изменения не означают нарушение идемпотентности настройки.

Воспроизведение — отдельно согласованная реальная локальная операция. Следуйте [руководству E2E](local-vm-e2e.ru.md), сохраняйте доступ к консоли гостя и оставляйте неудачные стенды для диагностики. Production-проверки требуют собственного разрешения и подготовки восстановления.
