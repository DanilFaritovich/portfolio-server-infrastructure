## Проверено на реальной инфраструктуре

Оператор подтвердил следующие завершённые прогоны для текущего обновления документации. При работе над документацией подключений к VPS и VM не было. Исходный JSONL-отчёт независимо не открывался; длительности production ниже предоставлены оператором из этого отчёта. Приватный inventory, адреса хостов, учётные данные, fingerprints и сырые протоколы намеренно не публикуются.

| Окружение | Подтверждённый объём | Время |
| --- | --- | --- |
| Отдельная Ubuntu VM через GNOME Boxes | Полный E2E с нуля, включая подготовку зависимостей, настройку инфраструктуры, управление пользователями, SSH и SWAP | Не предоставлено |
| Реальный production VPS | Все семь этапов инициализации: bootstrap, SWAP, Docker, SSH/UFW hardening, человеческий доступ, финальная защита SSH и обслуживание; SSH на 2222; успешные повторная проверка и проверка после перезагрузки | **36 минут 36,97 секунды**, по сообщённому JSONL-отчёту инициализации |

GNOME Boxes обозначает отдельное окружение VM-проверки. Автоматизированный стенд репозитория использует KVM/system libvirt, virt-install и cloud-init; самим Boxes он не управляет. Текущие [полный и независимые сценарии](local-vm-e2e.ru.md#изоляция-и-выполнение-сценария) описаны по реализации. Из последнего подтверждения не выводятся неуказанные релиз VM, вложенная топология, протокол независимых команд или измерения отдельных проверок.

### Продолжительность production-этапов

Оператор предоставил фактическое время из JSONL-отчёта инициализации. Измерения включают выполнение этапов и проверки, а также возможное время ожидания подтверждений внутри запуска.

| Этап | Продолжительность |
| --- | ---: |
| Bootstrap | 82,58 с |
| SWAP | 60,45 с |
| Docker | 582,12 с |
| Hardening | 388,54 с |
| Human | 369,85 с |
| SSH Security | 496,00 с |
| Operations | 217,44 с |
| **Общее время запуска** | **36 мин 36,97 с** |

Production-время относится к инициализации, а не установке зависимостей контроллера, последующим проверкам, перезагрузке или развёртыванию приложений. CLI пишет `elapsed_seconds` для каждого этапа, а для событий `stage=run` — время всего запуска. Терминал выводит путь приватного временного `portfolio-init-*.jsonl`; событие `run` / `completed` содержит полную длительность успешного запуска. Она включает время ответов на запросы во время выполнения, но не подготовку плана и входных данных до начала выполнения. Используйте итоговое событие каждого этапа; промежуточные события считают время от начала того же этапа, поэтому не суммируйте все события этапов и не считайте лог основанием для автоматического продолжения.

Production-подтверждение не устанавливает проведение упражнений удаления пользователей/отзыва ключей, циклов изменения/отключения SWAP или повторного provisioning с `changed=0` на VPS. Это отдельные возможности и результаты сценариев VM, а не гарантии production. Отчёт не содержит матрицы подтверждённых production-релизов ОС, performance benchmark или гарантии доступности.

## Историческая проверка VM

В более ранней записи оператор указал контроллер Ubuntu 26.04 и гостя Ubuntu Server 24.04 LTS. [PR #11](https://github.com/DanilFaritovich/portfolio-server-infrastructure/pull/11) фиксировал offline-проверки, подготовку/инициализацию стенда и независимую проверку SSH/sudo/Docker/UFW/systemd/финальной политики. В PR полная повторная сходимость и reboot оставались ожидающими после прерывания на подтверждении. Последующее подтверждение оператора зафиксировало финальную проверку, повторное выполнение/идемпотентность, сохранение состояния после reboot, создание и проверку пользователя, добавление/отзыв ключей, удаление пользователя и стенда. Эти исторические результаты не определяют production-окружение и не расширяют сведения о платформах последнего VM-отчёта.

## Offline-подтверждения и ограничения

`make check` проверяет YAML, offline Ansible lint, синтаксис playbook с примером inventory, синтаксис GitHub Actions и Python-тесты с синтетическими данными и имитацией внешних команд. [CI](../.github/workflows/ci.yml) устанавливает зависимости через `make deps-ci` и запускает `make ci` на Ubuntu 24.04. Offline-успех не доказывает реальный доступ, восстановление через консоль провайдера или live-идемпотентность.

Docker smoke-проверка создаёт, запускает и удаляет временный контейнер и может заполнить кеш образов. Эти ожидаемые runtime-эффекты отделены от сходимости provisioning. Результат VM или VPS не подтверждает все допустимые релизы Ubuntu, дистрибутивы/архитектуры контроллера или WSL2.

Для воспроизведения нужны отдельно разрешённые live-операции и проверенный доступ восстановления. Используйте [руководство оператора](operator-guide.ru.md#единая-инициализация) для VPS и [E2E-руководство](local-vm-e2e.ru.md) для собственного стенда. Сохраняйте состояние сбоя для диагностики; автоматические повторы, reset и удаление pending-свидетельств исключены.
